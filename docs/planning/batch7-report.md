## 1. Cold-start failure analysis (Batch 6 smoke run 2, `20261113-021610-9fc9`)
Evidence re-read from the preserved trace and logs: the failure was `page.goto("/")` ending `net::ERR_ABORTED` (request recorded with status -1, no failure text) on the **first navigation of the second browser context** (the supervisor's); the first context loaded the same URL normally. The Vite log shows only its start banner (no dependency re-optimisation, no restart, no error), Vite's dependency cache (`node_modules/.vite/deps`) pre-dated every run, and the same abort had been seen once before on the e2e UI (served by a different, non-Vite server). Conclusion: a **transport-level, intermittent abort of the first load of a fresh browser context**, not a Vite cold start and not an application fault; the exact trigger inside Edge is not established. Mitigations (Batch 7): UI readiness now also requires the entry module (`/src/main.tsx`) to be served; the demo spec retries only that first navigation, at most twice, and **records each retry** as a Playwright annotation plus any `requestfailed` text; the launcher report counts and prints them. No verification, authorization, priority or ticket step is retried.
