# Reliability and fault-injection results (Phase 7)

All scenarios run against an isolated PostgreSQL test database and local mock services with deterministic test-only AI backends
(fault handling does not depend on model quality). The disruptive scenario FI-10 stops and restarts this project's own PostgreSQL
container and is opt-in (`RUN_DISRUPTIVE=1`). Nothing is run against any external system.

```bash
RUN_DISRUPTIVE=1 python -m pytest tests/fault_injection -q
```

Reports (regenerated by that command): `evaluation/failure-reports/phase7/fi-report.json` and `fi-report.md` (initial conditions, fault,
expected, actual, recovery, final state, data-integrity result, duplicate external-action count, redacted log evidence, pass/fail).

## Mapping to the V4.1 specification

FI-01 to FI-10 keep the specification's identifiers and meanings (Part 20). FI-09b is an additional forced-race check of FI-09.
REL-01 to REL-04 are separate Phase 7 scenarios for dependency failures the FI list does not cover: LLM timeout or failure, embedding
or retrieval failure, invalid structured AI output (including a hallucinated asset id) and API-process restart. They do not redefine FI ids.

| Required coverage | Scenarios |
|---|---|
| Dependency unavailability, external API failure | FI-01, FI-02 |
| Connector timeout | FI-03 |
| Malformed or invalid responses | FI-04 |
| Database interruption and recovery | FI-10, REL-04 |
| LLM timeout or failure | REL-01 |
| Embedding or retrieval failure | REL-02 |
| Invalid structured AI output | REL-03 |
| Duplicate submission and ingestion | FI-04, FI-09, FI-09b |
| Concurrent approval and retry | FI-06, FI-07 |
| Isolation and injection | FI-05, FI-08 |

## Hardening found by the new scenarios

- Embedding failures previously surfaced as raw 500s; they now return 503 `embedding_unavailable` with `Retry-After`, and a failed upload stores nothing.
- A model-claimed asset id that does not occur in the report is now rejected for every model client, so the incident falls back to the
  deterministic rules and is held for human review.

## Limitations

Single-machine runs; the fault models are mocks (a lost response, 503/429, timeouts, a stopped database container), not real network partitions.
