# Phase 8 proposed optimisation experiments (PROPOSAL; nothing here has been run)

Status: **awaiting approval.** No experiment has been executed. All experiments use the dev split only, compare against the frozen baseline `baseline-20261112T035539Z` on identical inputs (paired per-query differences), keep the current
models (`qwen2.5:1.5b`, MiniLM), download nothing, and are bounded by the safety gates in `phase8-evaluation-protocol-v1.1.md` (any cross-tenant leak, unauthorised or duplicate external action, approval/review bypass, or loss of an existing security test = immediate rollback and stop).
Each experiment is a separate, reversible change behind a configuration switch; improvements are attributed separately to retrieval, prompting, deterministic validation, reranking and abstention logic (ablation on the final configuration).

## What the baseline says (dev split, repetition 1; Wilson 95% in the baseline report)
Recall@5 88.5% (observed met); grounded-answer coverage 62.1% (not met, above the 60% floor); citation correctness 85.7% (not met); claim support 97.7% (observed met); correct abstention 60.9% (not met); raw schema validity 100% on 34 calls; review rate 79.4% with grounded evidence for only 23.5% of incidents;
3 of 6 numeric vibration values hallucinated; p95 `/ai/ask` 12.4 s (within 15 s). The dominant failure modes are (a) 22 of 87 answers withheld because numbers or quotes failed verification, mostly multi-passage and troubleshooting questions; (b) 9 of 23 unanswerable questions answered, mostly "parameter missing from this model's manual" where a sibling model's page was used;
(c) incidents with no grounded guidance, driving review volume; (d) model-hallucinated numeric signals feeding deterministic priority.

## Experiments
Common measurement: per-query paired comparison with the baseline on dev (retrieval, grounding, extraction and latency metrics as defined in `phase8-metric-definitions.md`), 3 repetitions for model-dependent steps, Wilson intervals, no claim from differences inside the interval. Common rollback: any safety-gate failure, any new unsupported-answer or unsafe-acceptance case, p95 latency above 15 s without an offsetting quality gain, or no paired improvement on the primary measure.

## Execution rules
Order: E1-E4 (retrieval), then E5-E8 (generation and verification), then E9, then E10; the best retrieval configuration is carried forward. Every run (including failures) is logged in `phase8-optimization-log.md` with configuration hash and the paired results.
Selection rule (fixed now): the final configuration maximises dev grounded-answer coverage subject to citation correctness not below baseline, no safety-gate regression, and p95 `/ai/ask` <= 15 s; ties go to the simpler configuration. Then freeze code, prompts and thresholds, record hashes, and run test once and challenge once.
If any experiment needs new model weights, work stops and a separate approval is requested with model, licence, source, size and expected benefit. If a held-out item is ever viewed for diagnosis, the contamination is disclosed and instructions are requested before any claim of an unbiased evaluation.
